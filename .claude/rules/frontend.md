# Frontend and design system — binding

Derived from the decisions of 2026-10-31 (Expo, no web target, design from the user's artifact,
English copy through i18n keys) and `design-system/RULES.md`. Loads when a UI or design-system
file is touched.

## Stack

- One Expo + Expo Router app in `mobile/` for **iOS and Android only**. No web target: no `react-native-web`, no `.web.tsx`, no `Platform.OS === 'web'` branch, no `expo export --platform web`.
- Phone-first, one-handed: every flow works at 390 px and 430 px widths, portrait, with the primary action reachable at the bottom. Light and dark via the same token names (`colors.light` / `colors.dark`).
- Fonts: Inter (text) and Archivo (display) are loaded with `@expo-google-fonts/inter` and `@expo-google-fonts/archivo` through `useFonts` in the root layout before the first screen renders; `tokens.ts` names the families (`fontFamily`, `displayFontFamily`) — never a literal family name in a screen.
- File routes under `mobile/app/`; shared UI in `mobile/src/components/`; feature screens and their hooks in `mobile/src/features/<feature>/`; data only through repository hooks (`mobile/src/repositories/`), never `drizzle-orm` or `expo-sqlite` in a component.

## Design system

- Source of truth: the design artifact the user exports to `design-system/artifact/` and the files the designer agent derives from it during intake: `design-system/tokens.json`, `components.md`, `RULES.md`. **No agent edits the artifact.** A missing token, component or pattern is a design-system request to the user.
- `mobile/src/theme/tokens.ts` is generated by `node scripts/sync-design-tokens.mjs`; never hand-edit it. `node scripts/sync-design-tokens.mjs --check` and `node scripts/check-token-adherence.mjs` must pass.
- **Tokens only:** every colour, spacing, radius, font, size and shadow in `mobile/` comes from `tokens.ts`. No hex, pixel or font-name literal under `mobile/app/` or `mobile/src/` outside `src/theme/`; a justified exception carries `// token-adherence: allow — <reason>`.
- **Design intake gate:** while `design-system/tokens.json` carries `"_status": "starter"`, the designer's only permitted deliverable is the intake (tokens, components, RULES derived from the artifact, with citations); no screen spec is written against starter tokens. A re-exported artifact repeats the intake (`design-system/README.md`) before new screens are specified; open design requests (`components.md § Open requests`) are decided by the designer within the existing tokens and listed as deviations until the artifact answers them.

## Copy, testIDs and accessibility

- **i18n keys only.** Every user-facing string comes from `mobile/src/i18n/en.json` via `t('key')` with typed keys; no literal copy in JSX. English only in v1; keys are shaped `<screen>.<element>` so a second language is one file, not a refactor.
- **`testID` on every interactive element and list row**, shape `<screen>.<element>[.<id>]`, taken from the `design.md` testID table — Maestro flows select by `id:`. A screen without them is **B**.
- `accessibilityRole` and an i18n `accessibilityLabel` on every control, icon-only buttons included; hit targets ≥ 44 pt on iOS and ≥ 48 dp on Android (ruling R-18), smaller visuals extended with `hitSlop`; status never by colour alone; reduced motion respected.
- Unbounded lists use a virtualised list (`FlatList` / `FlashList`) per `react-native-best-practices`.

## Verification (before any frontend completion signal)

From `mobile/`, output redirected to a file and grepped, never streamed:

1. `npx tsc --noEmit` — zero errors
2. `npx jest --watchAll=false` — zero failures
3. From the repo root: `node scripts/sync-design-tokens.mjs --check` and `node scripts/check-token-adherence.mjs` — exit 0
4. `npx expo-doctor` — no failed checks
5. Phase B only — simulator smoke on a **dev-client build**: `npx expo run:ios` on a booted simulator (the database is SQLCipher, so Expo Go cannot run the app), open the routes you touched, `xcrun simctl io booted screenshot`, then **stop Metro**. CocoaPods or a simulator missing → record `INFRA UNAVAILABLE` for this row and report it as a PO action; never substitute Expo Go or a mocked database.

A failing test is fixed at its root — fixture, clock, data or the bug. Never loosen a validation or an assertion to make a test pass.
