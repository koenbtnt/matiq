# matIQ — Claude Code Instructions

A native iOS + Android app for BJJ practitioners: plan a session and its focus areas → train → log what you actually
worked on → review it → see which areas are improving or lacking. Everything — taxonomy and algorithm weights
included — is editable by the user. The binding rules live in `.claude/rules/`.

## Environments (hard rule)

- **Development = this machine.** Expo **dev-client** builds on the iOS simulator (`npx expo run:ios`; the database is SQLCipher,
  which Expo Go cannot run); Maestro against that build. Android via EAS Build until a local SDK exists (`docs/carry-over.md`
  CO-03). There is no server, no account and no cloud data in v1.
- **All user data stays on the device** (`.claude/rules/privacy.md`). Never commit `.env*`, signing material or store credentials.

## Language

- All documentation is written in English: `docs/`, READMEs, `design-system/RULES.md`, ADRs, code comments and generated file headers.

## Source of truth

- `docs/PRODUCT.md` (product spec) and `docs/decisions.md` (binding, dated decisions) — written in sprint 0. Plan against them; don't re-litigate them.
- Design: the user's Claude Artifact exported to `design-system/artifact/`; the designer derives `design-system/tokens.json`, `components.md`, `RULES.md` from it (intake, `design-system/README.md`). `mobile/src/theme/tokens.ts` is generated by `node scripts/sync-design-tokens.mjs` (CI runs `--check`); never hand-edit it. The intake ran on 2026-10-31 (`tokens.json` v1 from canvas v13); a re-export of the artifact repeats the intake before new screens are specified.
- `/Users/koen/Projects/matiq/matiq-legacy` is reference material only (the domain model); don't copy its code.

## Branching and releases (ADR 0001)

- `develop` is the integration branch and the GitHub default; `main` holds only released code.
- `feature/<sprint-slug>` and `chore/<slug>` are cut from `origin/develop` and PR into `develop`.
- **Release** = the user's PR `develop → main`, then the user tags the merge commit `vX.Y.Z` (semver) on `main`.
- **Hotfix**: a normal fix via `develop`, or `hotfix/<slug>` cut from `origin/main`, PR into `main`, then a back-merge PR `main → develop`.
- Regular merges only (no squash/rebase); every merge is the user's after green CI. No agent opens a release or hotfix PR, tags, merges locally, or pushes to `develop` or `main`. Local `develop`/`main` are stale by design: compare against `origin/develop` (`origin/main` on a hotfix branch).

## Sprint workflow

Each sprint lives in `docs/<sprint-slug>/` — a short kebab-case name (e.g. `docs/product-spec/`), **not a number**; the branch is `feature/<sprint-slug>`, cut from `origin/develop`. Artefacts: `plan.md` → `design.md` → `review-1.md` → build → `data-contracts.md` (data-coder; prerequisite for frontend integration) → `test-report.md` → `docs-report.md` → `review-2.md` → `done.md`.

- **Agents** (`.claude/agents/`): `orchestrator` → `planner` → `designer` (reads `plan.md`; copy table + testID table) → `reviewer-design` (`review-1.md`, `-recheck`) → `data-coder` ∥ `frontend-coder` phase A (UI on typed mocks) → `frontend-coder` phase B (integration, after `data-contracts.md`) ∥ `tester` authoring → `tester` run (Maestro) → `documenter` (`docs-report.md`) → `reviewer-code` (`review-2.md`, `-recheck`). Two rework rounds per artefact, then escalate to the user.
- `plan.md` and `design.md` open with a `§0 Summary for builders`; coders and the tester read §0 plus named sections only. Build/test results are recorded once per sha in `docs/<sprint-slug>/verify.md` (+ `verify.json`) and never re-run downstream. `progress.md` (orchestrator-owned) keeps a `## Current state` block at the top — the cold-start read. Known failures and deferred items go in `docs/carry-over.md`. External lookups go into `docs/stack-notes.md`.
- Work on feature branches; PRs go to **`develop`** (see Branching and releases).
- Tests: Jest in `mobile/src/{db,domain,repositories}/**/__tests__/` (data-coder, on real SQLite), Jest in `mobile/__tests__/` and `mobile/src/{components,features,hooks}/**/__tests__/` (frontend-coder), Maestro flows in `e2e/maestro/` (tester; local only, CO-01). Frontend verification: `npx tsc --noEmit`, `npx jest`, `node scripts/sync-design-tokens.mjs --check`, `node scripts/check-token-adherence.mjs`, `npx expo-doctor`, a simulator smoke.
- **Documentation standard** (`.claude/agents/documenter.md`): arc42 in `docs/architecture/` with C4 diagrams in Mermaid; ADRs (MADR) in `docs/adr/`; data dictionary, ERD and schema changelog **generated** into `docs/data-model/` from the Drizzle snapshot + `mobile/src/db/schema/descriptions.json`; user stories with Gherkin in `docs/requirements/`. Docs change in the same PR as the code.
- **Binding rules** live in `.claude/rules/`: `privacy.md` (always loaded: on-device data, no analytics, export/erase readiness, secrets), `data.md` (Drizzle, migrations, sync seam, domain purity), `frontend.md` (Expo, tokens, i18n keys, testIDs), `e2e.md` (Maestro), `docs.md` (sprint artefacts).
- Edit scopes are enforced by `.claude/hooks/path-guard.sh` and `bash-guard.sh` (explicit `git add` paths, no force push, no bare `main`/`develop` compares, no pushes to either, no secret files staged; scoped agents may not run inline interpreter code, stdin scripts or scripts outside the repository — rule 6). `CLAUDE.md` and `.claude/**` are owned by the user; no agent edits or stages them. An agent whose guard refuses a path its definition grants reports `CODING BLOCKED` — never a copy-in via another subagent (ruling Q1, 2026-11-01).
- Agent definitions and their hook scopes are read once per session: after any change under `.claude/`, start a new session before the next orchestrator or agent spawn.
- When compacting, preserve: the active sprint slug and branch, the list of modified files, every `verify.md` row at HEAD, open rulings, and the next action from `progress.md ## Current state`.

## Commands

```bash
cd mobile && npx tsc --noEmit && npx jest --watchAll=false        # typecheck + unit tests (data layer on better-sqlite3)
node scripts/sync-design-tokens.mjs --check                        # mobile/src/theme/tokens.ts matches design-system/tokens.json
node scripts/check-token-adherence.mjs                             # no hex/px/font literals in UI code
cd mobile && npx drizzle-kit generate && git diff --exit-code -- drizzle/   # migrations in sync with the schema
cd mobile && npx expo-doctor                                       # config and dependency health
cd mobile && npx expo run:ios                                      # dev-client build on the booted simulator (CocoaPods, CO-14); Expo Go cannot run SQLCipher
maestro test -e METRO_URL=http://localhost:8081 e2e/maestro      # E2E on the booted simulator against the dev-client build (Metro port per run)
npm run test:hooks                                                 # exit-code tests for .claude/hooks (scripts/claude/hooks.test.sh)
node scripts/docs/gen-data-model.mjs && node scripts/docs/gen-changelog.mjs   # regenerate docs/data-model/
```

Dev-server previews for the desktop app: `.claude/launch.json` (`expo-dev-client`, `expo-go-ios`); the simulator itself
is driven with the desktop app's iOS Simulator tool or `xcrun simctl`. Personal permission allows go in
`.claude/settings.local.json` (gitignored); `.claude/settings.json` is team-wide. PO install actions:
`docs/agent-tooling/plan.md §2`.
