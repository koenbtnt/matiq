## §3 Data model (data-coder) — migration `0001_foundation`

Conventions (unchanged from `product-spec §4`): `text` unless stated; booleans `integer` 0/1 with `check(col IN (0,1))`; dates `YYYY-MM-DD` local with `check(col GLOB '[0-9][0-9][0-9][0-9]-[0-1][0-9]-[0-3][0-9]')`; timestamps ISO-8601 UTC text. Seam on every table: `id` text PK, `created_at`, `updated_at` NOT NULL, `deleted_at` nullable. **Imported tables** add `origin NOT NULL check(origin IN ('seed','user'))`, `source` nullable `check(source IS NULL OR source IN ('grapplemap','grapple-flows','curated'))`, `check(origin = 'user' OR source IS NOT NULL)`, `source_id`, `source_version`, `user_edited_at` (all nullable) and a partial unique index on `(source, source_id) WHERE deleted_at IS NULL AND source_id IS NOT NULL`. Every enum/range is a `check()`; "live-unique(cols)" = partial `uniqueIndex … .where(sql\`deleted_at IS NULL\`)`. FK columns get a plain `index()`. `PRAGMA foreign_keys = ON` is set at open (§5) and in every Jest `beforeEach`.

## §6 Taxonomy seed pipeline (data-coder)

### §6.1 Measured facts (planner, 2026-11-01, read-only fetch of `raw.githubusercontent.com/Eelis/GrappleMap/master/GrappleMap.txt`; data-coder appends them to `docs/stack-notes.md` at vendoring)
- 2,674,097 bytes, sha256 `734c5af03958f7384af1c09b18bf06500748a8c505573e5be9a48174ddcfb74e`; no blank lines; 2086 records = 601 positions (exactly one pose) + 1485 transitions (≥ 2 poses).
- Record grammar: one unindented **name** line (literal `\n` inside = line break; 203 names contain `w/`; 241 names are duplicates, 11 are `...`, some start with `todo`), then zero or more unindented **description** lines (free text; 349 records have one), interleaved with meta lines `tags: <[a-z0-9_]+ …>` (919), `ref: <citation>` (1208 over 1058 records; 1025 transitions, 3 positions), `properties: <words>` (1244: `top` 616, `bottom` 558, `detailed` 159, `bidirectional` 38, `sweep` 2, `transitive` 1); then the **pose block**: lines indented by four spaces, 69 characters each, alphabet exactly `0-9A-Za-z` (62), four lines per pose (33,292 lines = 8,323 poses).
- Parser rule that yields 2086: a new record starts at the first unindented line after a pose line; everything unindented before the next pose line belongs to the record.
- Endpoints are **not** string-identical: a transition's first pose equals a position's pose verbatim in 742/1485 cases, the last pose in 351/1485 — canonicalisation (F-12) is mandatory, as `stack-notes.md` ("endpoints may be reoriented") says.
- Unverified (reference reading for the data-coder, no fetch at build time): the decode of a pose (276 chars = 138 values × 2 base-62 digits = 2 players × 23 joints × xyz, scale/offset per GrappleMap `src/persistence.cpp`), the joint order and left/right pairs for mirroring, PR 5's file naming. Record what the reference says in `stack-notes.md`.

### §6.3 Stages (WHAT, deterministic, no network, no `Date`/`Math.random`)
1. **split/join** — `join(records/) === GrappleMap.txt` byte-for-byte (sha256 in `SOURCE.md`; test); the original file is not committed.
2. **validate** (PR 4 rules reimplemented): pose lines exactly 69 chars of the alphabet; pose count a multiple of 4; positions exactly 1 pose, transitions ≥ 2; property words ∈ the measured set; tags match `[a-z0-9_]+`; non-empty name. Any error fails the run with record index + line.
3. **decode + canonicalise** (`pose.ts`): per pose and per variant (player order × mirror = 4): translate the ground-plane centroid of all joints to the origin, rotate about the vertical axis so the player-0→player-1 hip-centre vector lies on +x, quantise to a grid (ε, tuned so every position's own pose maps to a unique key), serialise as the key.
4. **resolve** (`resolve.ts`): index positions by all variant keys; a transition's first pose → `from`, last pose → `to`; miss → nearest position by RMS joint distance under `ε_max`; still none → unresolved (edge dropped, node kept). `report.json` records resolved/nearest/unresolved counts; acceptance ≥ 95 % resolved both ends, else the data-coder tunes ε and reports.
5. **names** (`names.ts`, `name-rules.json`): join `\n` with a space, token map (`w/`→`with`, `ctrl`→`control`, `rnc`→`RNC`, `vs`→`vs.`, …), sentence case; placeholders (A-32); slug = kebab, collisions `-2`, `-3` in record order; `source_id` = `gm:<record index>` (stable even if names change), reverse edges `gm:<index>#rev`.
6. **edge types** (`edgeTypes.ts`, F-13): priority over the transition's own tags — SUBMISSION {`kimura armbar triangle rear_naked_choke guillotine darce anaconda omoplata monoplata gogoplata twister neck_crank calf_crank americana ezekiel heel_hook kneebar toe_hold straight_ankle_lock arm_triangle north_south_choke loop_choke bow_and_arrow baseball_choke peruvian_necktie japanese_necktie electric_chair banana_split`} > TAKEDOWN {`*_takedown throw trip ankle_pick te_waza`} > GUARD_PASS {`pass pass_* knee_slice leg_drag`} > SWEEP {`sweep *_sweep`} > ESCAPE {`escape bridge`} > TRANSITION; name keywords (`sweep`, `pass`, `escape`, `takedown`, `choke`, `lock`, `bar`, `crank`) as fallback; `edge-types.json` overrides by `source_id` win. SUBMISSION ⇒ `to_position_id = null` (A-26); `bidirectional` ⇒ second TRANSITION edge (A-31); `properties: top|bottom` → `perspective`.
7. **curated overlay** (`curated.ts`): `core.json` entries by `source_id` set `tier = CORE`, override `canonical_name`/`name`, add aliases (`source = curated`) and `parent`; `aliases.json` maps grapple-flows slugs (read from the vendored `data/taxonomy/grapple-flows/` file, never retyped) to our position/technique `source_id`s and emits them as `source = grapple-flows`, `source_id` = their slug, `source_version` = the vendored commit date; `ATTRIBUTION.md` (licence, URL, commit) → `attribution.json`; `gi.json` adds hand-authored techniques (`source = curated`, `applies_to = GI`, endpoints by `source_id` of positions). Core target: ≈ 40–60 positions, ≈ 150 techniques (R-28); the converter fails if `core.json` references an unknown `source_id`.
8. **ids** (`ids.json`, A-29): every emitted row's `id` comes from the registry keyed `${source}:${source_id}`; a missing entry fails in check mode; `--mint` appends UUID v4 entries (sorted by key) and is the only non-deterministic operation, run by a human before commit.
9. **resources** (F-15, A-27): distinct `ref:` strings → `resources` rows (`source_id = ref:<sha1 of the string>`), `resource_links` to each citing technique (`source_id = <technique source_id>|<resource source_id>`).
10. **emit** (`emit.ts`): JSON with sorted keys, 2-space indent, trailing newline, arrays ordered by `source_id`; `taxonomy.json` = `{ release, grapplemapSnapshot, positions[], techniques[], aliases[], resources[], resourceLinks[] }`; `catalog.json` = `{ release, sessionTypes[], subjects[], resourceTypes[] }` (R-03 six types; A-4 six subjects; Instructional, Video, Article, Book, Other); `report.json` counts (records, resolved, unresolved, per type, core sizes).

## §10 Edge cases (full)

- **Key present, no database** (fresh install, or `clearState` on an iOS simulator where the keychain survives): open creates a new encrypted file with the existing key — normal path, no error.
- **Database present, key missing** (keychain wiped, device restore with the file backed up): unreadable by design → `DB_KEY_MISSING_FOR_EXISTING_DB` error screen; the only exit is the explicit reset (dev) / erase (sprint 3); never silently recreate.
- **Wrong key / plaintext file** (a build without `useSQLCipher` ran once): `sqlite_master` read fails → `DB_KEY_REJECTED`; same screen; `verify.md` notes that plaintext→encrypted migration is not supported (`web-and-config.md:96`).
- **Secure store throws** (locked device at cold start on iOS): `DB_KEY_UNAVAILABLE`, retry action; never fall back to an unencrypted open.
- **Second connection**: `withExclusiveTransactionAsync` and `useNewConnection: true` are forbidden (unkeyed); a test greps the repositories for both.
- **Seeding twice / a newer release**: idempotent by `(source, source_id)`; user-edited (`user_edited_at`) or soft-deleted seed rows are skipped and reported; `origin = 'user'` rows untouched; a slug clash with a user row suffixes `-gm`; an older release is refused.
- **Unresolved GrappleMap endpoints**: the edge is dropped, both nodes stay; counts in `report.json`; the Library never shows an edge without a `from`.
- **Submission edges**: `to` nulled (A-26); the former target node stays EXTENDED; a later curated release may retire it (`retired` list in `taxonomy.json`; soft-deleted only when untouched by the user).
- **Alias search hits a removed row**: pickers filter `deleted_at IS NULL` on positions/subjects/techniques and their aliases; session detail renders a removed focus with the "(removed)" suffix (`removed: true`).
- **Planned focus un-ticked at log time**: row kept `is_planned = 1, is_actual = 0`, no rating/flag allowed (checks) — the gap signal input (F-20). Ticking a non-planned focus creates `is_planned = 0, is_actual = 1`.
- **Logging a PLANNED session changes its type or time**: allowed; `local_date` recomputed from the new `starts_at` and the device zone (ADR 0016); `completed_at = now`.
- **Editing a COMPLETED session**: same screen (review mode); `reviewed_at` set on the first save that touches rating / what_worked / what_failed; status never regresses to PLANNED.
- **Quick log with two planned sessions today**: new session with the last-used type (rule in `quickLog.ts`); Home lists both planned ones for explicit "Log it".
- **Stale planned sessions** (`local_date < today`, still PLANNED — R1-04: last night's plan is stale this morning, not after 24 h): shown as unlogged with "Log it" / "Skip" (`sessions.skip`, undoable); they count as planned-not-trained for the sprint-2 gap signal. The `product-spec §6` 24 h rule stays the algorithm's definition; Home's bucket is the user-facing one.
- **Techniques on a planned-only focus**: attaching a technique to a focus row with `is_actual = 0` is rejected (`TECHNIQUE_REQUIRES_ACTUAL`); un-ticking a focus in edit mode drops its technique attachments after the user confirms via the inline reason text (no dialog).
- **Time zones / DST**: `starts_at` UTC, `local_date` fixed at write in the device zone; Monday weeks; Jest runs the date tests under two `TZ` values (CO-06).
- **Counts and ratings**: steppers cannot go below 0 / outside 1–5; the domain still validates (`COUNT_NEGATIVE`, `RATING_OUT_OF_RANGE`) because the input may come from a restored draft.
- **Session-level submissions vs aggregates**: aggregates authoritative; submission rows are detail; `deriveAggregates` offered, never applied silently (product-spec §6).
- **Rank**: adult only in sprint 1; stripes ≤ 4 unless BLACK; `awarded_on` ≤ today; current = latest live row by `awarded_on` then `created_at`.
- **Settings read without UI**: `library.showExtended` and `log.detailedRounds` default off; the Library and Log screens read them so sprint 2 only adds switches.
- **One-handed / mat-side**: required fields first, primary action bottom-anchored, keyboard avoidance with the action bar (DSR-23 — designer decides within tokens).
- **Dark mode**: tokens only; `theme.override` row exists (SYSTEM) but no UI until sprint 2 (DSR-21).
- **Maestro reach**: every interactive element has a testID; `/dev/reset` reseeds; flows never depend on each other.
- **Export/erase readiness**: no user data outside the database; the key is not user data; `resetDatabase` is the erase primitive.
