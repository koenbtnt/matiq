## Context and problem

Sprint 0 specified 20 tables (`docs/product-spec/plan.md` §4). Sprint 1 builds three screens that touch only some of them. The migration history is the schema's record, so the split of tables across migrations is a one-time choice. "Unique among live rows" (`data.md`) must hold in SQL, not only in the UI.

## Decision drivers

- Later sprints should only add columns and tables, not rework foreign keys (`sessions.cycle_id`, `slots` link).
- Constraints belong in the schema (`data.md`).
- The UI needs a domain error code, not a raw SQLite constraint message.

## Considered options

- One generated migration `0001_foundation` with all 20 tables, including `cycles`, `cycle_focuses` and `slots` without repositories (chosen, F-01, A-24).
- Create cycles and slots tables in sprint 3: rejected, `sessions.cycle_id` and `sessions.slot_id` would need a rebuild migration.
- Uniqueness only in the domain layer: rejected, a bypassing writer corrupts data.
- Partial unique indexes `WHERE deleted_at IS NULL`, plus a domain pre-check that throws first (chosen, F-02).

## Decision outcome

- `mobile/drizzle/0001_foundation.sql` is generated by drizzle-kit from `mobile/src/db/schema/`; `0000_init` (app_meta) stays. Sprint 3 adds reminder columns only.
- Uniqueness among live rows is a Drizzle `uniqueIndex().where(...)`; repositories pre-check and throw `FOCUS_DUPLICATE`, `ALIAS_DUPLICATE`, `ROUND_NO_DUPLICATE`. A violation that reaches SQLite is a bug and has a test.
- Deltas against the sprint-0 schema: `techniques.perspective` (TOP or BOTTOM, null) records GrappleMap's `properties: top|bottom` (A-31); `source` holds the short source name and `source_version` the snapshot or release (A-15; `data.md` was amended in d0131d3 to `source in ('grapplemap','grapple-flows','curated')`).
- Planned-but-unticked focus rows stay as `is_planned = 1, is_actual = 0` (the gap signal of PRODUCT §7). Rating, needs-work, hit and caught counts, and technique attachments exist only on actual rows: three `check()` constraints plus the domain rules `TECHNIQUE_REQUIRES_ACTUAL` and `COUNTS_REQUIRE_ACTUAL` (F-20, R1-05).

## Consequences

- Three tables (`cycles`, `cycle_focuses`, `slots`) carry descriptions and migration tests with no repository: accepted cost.
- If the PO rules against A-24, those tables and two foreign-key columns leave 0001 (nothing has shipped).
- The dictionary and ERD in `docs/data-model/` are generated from this migration's snapshot.
